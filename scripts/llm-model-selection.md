# MapleFox 桌宠 · 本地 LLM 模型选型说明

> 为桌宠「基础对话」功能确定本地模型选型。
> 决策形态：**单版本定稿**（不做设置档位 / 不做多模型可选 UI），在 3B 与 4B 之间择一。

---

## 1. 为什么本地部署

- 对话功能需要一个 LLM 大脑；云端 API 每次调用都计费、且依赖网络——桌宠要常驻桌面，不能接受断网就哑火。
- 本地部署的收益：**零成本、离线可用、对话内容不出本机**（隐私）。
- 代价：模型能力受本机硬件限制 → 必须选「够小、够快」的轻量模型。

## 2. 目标硬件（开发机）

| 部件 | 配置 | 在选型中的角色 |
|:---|:---|:---|
| CPU | AMD Ryzen 7 7735HS（8核16线程，Zen3+） | **推理主力** |
| 内存 | 32GB DDR5-6400 双通道 | 容量充足；带宽是速度关键 |
| 显卡 | Radeon 核显（4GB 共享显存） | **不可用于 LLM 推理** |

关键认知：

1. **核显在 Windows 下无法有效跑 LLM**（AMD ROCm 不支持 iGPU，Vulkan 路线实验性且通常更慢）→ 推理完全走 CPU，显卡 4GB 这条可以忽略。
2. CPU 推理的速度瓶颈是**内存带宽**：权重在内存里搬运得快，出字才快。DDR5-6400 双通道是笔记本天花板级别，因此本机跑小模型会明显比普通 DDR4 内存本流畅。
3. 结论：模型选型只看 **内存占用** 与 **CPU 推理速度**，与显存无关。

## 3. 候选与结论

候选收敛为 **3B / 4B** 两档（均以 Q4_K_M 量化为前提）：

| 指标 | 3B（Qwen2.5-3B-Instruct） | 4B（Qwen3-4B） |
|:---|:---|:---|
| 量化后大小 | ~1.9 GB | ~2.5 GB |
| 常驻内存占用（含运行开销） | ~2-3 GB | ~3-3.5 GB |
| 开发机速度（R7 7735HS） | ~30 tok/s | ~20-25 tok/s |
| 低配机（16G 内存 / 6核） | 流畅 ~20 tok/s | 流畅 ~15 tok/s |
| 8GB 内存老机器 | 可跑 | 偏紧、勉强 |
| 中文闲聊 + 人设质量 | 够用 | 更好，人设更立得住 |
| 一句回复体感（~50 token） | ~1.5-2.5 秒 | ~2-3 秒 |

**结论：定版推荐 4B（Qwen3-4B，Q4_K_M）**

- 开发机流畅（20+ tok/s），低配机（16GB 内存 / 6核）也流畅；
- 4B 在中文闲聊与角色扮演上明显强于 3B，桌宠的「人设感」更稳；
- 唯一需要退回 3B 的情形：**确定要支持 8GB 内存级别的老机器**。本项目单版本交付，若分发目标以近五年内的笔记本为准，4B 即可覆盖。

> 备注：若届时 Ollama 仓库已有更新的 Qwen 4B 指令版（如 Qwen3.x-4B），以同档位最新版为准，选择逻辑不变。

## 4. 为什么不是更小 / 更大

- **1.5B**：省内存但明显变笨——中文闲聊容易跑偏、接不住 OC 人设，角色显得「傻」；桌宠是高频交互，体验落差会被放大。淘汰。
- **7-8B**：质量更好，但本机纯 CPU 只有 8-12 tok/s，一句话要 5-6 秒，桌宠场景体感卡顿；低配机更跑不动。淘汰。
- **14B+**：不在考虑范围。

判断标准：「模型小到 CPU 能快速搬完」优先于「模型大到塞进内存」。桌宠是轻任务（短句、闲聊、性格化），3B/4B 已覆盖需求。

## 5. 部署与调参要点（落地备忘）

- **推理服务**：Ollama（`ollama pull qwen3:4b`），自带 OpenAI 兼容 HTTP 接口，桌宠侧当普通 HTTP 请求调用。
- **接口层**：把 `base_url` + 模型名抽象成两处配置，日后想切云端 API（如 DeepSeek）零成本改配置。
- **⚠️ Qwen3 务必关闭 thinking**（`/no_think` 或 API 参数），否则回复前先思考 1-2 秒，延迟直接翻倍。
- **桌宠对话参数**：`max_tokens` 64-128（短句自然）；开启 streaming（首字即出，体感快）；`temperature` ~0.8（性格更鲜活）。
- **对话历史**：保留最近 10-20 轮即可，桌宠不需要长上下文（131K 上下文不买单，只会增加内存占用）。
- **常驻开销**：模型加载后常驻内存 ~3-3.5GB，与桌宠本体共存无压力（开发机 32GB）。

## 6. 定版前建议做一次实测

3B 与 4B 都只需 Ollama 一条命令即可拉取，成本极低。建议：

1. 用同一段 OC 人设 system prompt，分别跑 10 句对话；
2. 对比两件事：**速度**（tok/s 是否达标）与**质量**（人设是否立得住、中文是否自然）；
3. 预期结论是 4B；若在目标低配机上实测 4B 卡顿，则退回 3B。
